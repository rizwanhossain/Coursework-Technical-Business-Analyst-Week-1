# Agent Skill: Transform Process Issues to Jobs To Be Done (JTBD)

## Overview
This skill transforms stakeholder quotes about process pain points at Legacy Trust Bank into Jobs To Be Done (JTBD) statements. JTBD reframes problems as user needs, enabling solution-focused thinking.

## When to Use This Skill
- Converting stakeholder complaints into actionable user needs
- Translating current-state process issues into desired future outcomes
- Creating empathy-driven problem statements for redesign efforts
- Prioritizing improvements based on what users are actually trying to accomplish

## JTBD Format
```
When I [X], I want [Y].
```

Where:
- **[X]** = The core action or task the user is attempting
- **[Y]** = The change or outcome they need to accomplish it successfully

## Transformation Rules

### 1. Identify the Core Task (X)
Extract the fundamental activity from the quote, not the tool or system causing problems.
- Look for verbs: contact, queue, record, track, approve, resolve, etc.
- Remove blame or technical details
- Focus on what the user is *trying to do*, not what's broken

### 2. Identify the Desired Outcome (Y)
Reframe the problem as a positive change that would enable success.
- "Fix X" becomes "accomplish Y"
- Focus on capability, not blame
- Include the improvement or result they need

### 3. Keep it User-Centric
- Use the perspective of the person experiencing the problem
- Frame from their workflow and goals, not organizational systems
- Avoid solution prescriptions

## Example Transformations

### Example 1: Duplicated Work
**Original Quote:** "The collections database does not sync with the email tracker, so representatives often re-contact customers who were already promised callbacks."

**JTBD:** When I attempt to contact a customer, I want to see their complete contact history and promises so I don't re-contact them.

---

### Example 2: Poor Account-Status Visibility
**Original Quote:** "We have no way to tell whether a customer is genuinely unable to pay or simply avoiding contact."

**JTBD:** When I assess a customer's situation, I want clear indicators of payment capability versus engagement intent so I can tailor my approach.

---

### Example 3: Delayed Follow-up
**Original Quote:** "Cases get stuck in 'pending callback' status indefinitely because the callback date is never enforced."

**JTBD:** When I promise a customer a callback, I want the system to track and escalate the deadline so the callback happens on time.

---

### Example 4: Change Resistance
**Original Quote:** "Representatives are afraid of the portal because they think it will take away their job, not because it won't work."

**JTBD:** When a new tool is introduced, I want to understand how it will change my role so I can feel confident in adopting it.

---

### Example 5: Lack of Confidence in Numbers
**Original Quote:** "The finance team cannot forecast recovery revenue because they do not trust the activity data."

**JTBD:** When I forecast recovery outcomes, I want reliable activity data so I can make confident financial decisions.

---

## Application Process

### Step 1: Extract the Issue
Read the stakeholder quote and identify what problem is blocking their work.

### Step 2: Reframe as an Action
Identify the task or workflow: "When I [contact customers / record data / track cases / make decisions / etc.]"

### Step 3: Define the Success Outcome
What outcome would enable them to accomplish their task? "I want [visibility / automation / integration / clarity / etc.]"

### Step 4: Complete the Statement
Combine into the JTBD format: "When I [X], I want [Y]."

### Step 5: Validate
Check that:
- The JTBD addresses the core frustration, not a symptom
- It focuses on user need, not solution
- It's specific enough to guide design but broad enough to allow multiple solutions
- Someone reading it would understand what success looks like

## Common JTBD Categories at Legacy Trust Bank

### Visibility & Tracking
- When I [check account status], I want [unified view across systems]
- When I [review case history], I want [accurate, consolidated record]
- When I [manage my workload], I want [visibility into case progress]

### Process Clarity & Consistency
- When I [handle a case], I want [clear, standardized process]
- When I [assess case complexity], I want [definitive classification system]
- When I [report on activity], I want [consistency in definitions and metrics]

### Integration & Handoffs
- When I [transition a case], I want [complete context passed forward]
- When I [contact a customer], I want [information from all previous interactions]
- When I [end my shift], I want [clear handoff of pending items]

### Decision Support
- When I [make a business decision], I want [timely, reliable data]
- When I [assess customer situation], I want [complete profile and history]
- When I [prioritize work], I want [clear criteria for complexity/urgency]

### Capability & Adoption
- When I [learn a new tool], I want [clear training and support]
- When I [change my workflow], I want [confidence that my role is secure]
- When I [implement a solution], I want [proof it doesn't create compliance risk]

## Output Format
When applying this skill, generate JTBDs in a structured list:

```
## Converted JTBDs

| Original Issue | JTBD Statement |
|---|---|
| [Quote from stakeholder] | When I [X], I want [Y]. |
```

Or as a narrative list:

```
**When I contact a customer**, I want to see their complete contact history and promises so I don't re-contact them.

**When I assess a customer's situation**, I want clear indicators of payment capability versus engagement intent so I can tailor my approach.
```

## Tips for Effective JTBDs

- ✅ Do: Focus on the user's perspective and workflow
- ✅ Do: Make it outcome-oriented and positive
- ✅ Do: Keep it specific to one need per statement
- ❌ Don't: Prescribe solutions ("I want a portal")
- ❌ Don't: Use technical jargon or system names
- ❌ Don't: Mix multiple needs in one statement
- ❌ Don't: Focus on the broken tool instead of the user goal
